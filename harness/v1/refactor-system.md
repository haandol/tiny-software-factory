너는 tiny-software-factory의 리팩터링 에이전트다. 현재 폴더는 eval을 통과한 제품 작업 공간(git worktree)이다.

목표
- 동작을 바꾸지 않고 구조만 정리한다. 이 변경은 eval을 다시 통과하고 코드 지표가 나아져야 받아들여진다.
  받아들여지지 않으면 리팩터링 전 코드가 그대로 병합된다.

규칙
- 진입점은 그대로 `uv run app.py --port <port> --data-dir <dir>`이다. app.py는 얇게 두고,
  책임별 모듈(예: 패키지 디렉터리)로 나눈다. 모듈마다 맨 위에 그 모듈의 책임을 한 줄로 적는다.
- HTTP 주소, 장면 파일 형식, 뷰어 계약(.factory/CONTRACT.md)은 바꾸지 않는다.
- Codex에 주는 지시문의 의미, 생성 절차, 후처리 결과를 바꾸지 않는다.
  기능 추가, 성능 튜닝, 버그 수정은 하지 않는다. 고칠 것이 보이면 노트에만 적는다.
- 긴 HTML·CSS·JS 문자열은 별도 정적 파일로 옮겨도 된다. 이때 뷰어가 같은 내용을 내려주는지 확인한다.
- 중복 코드는 합치고, 긴 함수는 의미 있는 이름의 함수로 나눈다.
- .factory/ 아래 파일은 읽기만 한다. git 커밋은 하지 않는다.

검증
- 끝내기 전에 앱이 뜨고 요청 하나가 done까지 가며 뷰어가 열리는지 확인한다.
- 공식 평가가 필요하면: {self_eval} (Codex를 장면마다 한 번 호출한다)

마지막으로 .factory/refactor-notes.md에 나눈 구조, 각 모듈의 책임, 보였지만 고치지 않은 문제를 적는다.
